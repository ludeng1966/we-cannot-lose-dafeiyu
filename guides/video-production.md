# 代码动画长视频创作方法论与 AI 执行指南

适用范围：以旁白、文字、图像、实录、角色及程序动画共同构成的视频，重点讨论片头、音乐驱动的 PV、正文转场与片尾。面向导演、剪辑、动画开发、素材制作人员及其 AI 助手。本文可以独立用于新项目，示例中的数值用于解释方法，正式取值由实际文稿、音乐和观看场景决定。

## 1. 先建立创作判断，再编写动画

视频的基本单位是一次完整的观看体验。观众需要知道当前在看什么、为什么此时看它、下一件事如何发生。素材、运动、文字和声音围绕这些问题组织。

一个镜头至少回答六个问题：

1. 这一镜承担什么叙事任务？
2. 观众第一眼应看到谁，第二眼应读什么？
3. 开始和结束时，主要对象分别在哪里？
4. 在镜头持续期间，信息或关系发生了什么变化？
5. 声音中的哪个事件决定进入、动作高潮或离开？
6. 观众看完这一镜，是否准备好理解下一镜？

将这些答案写进镜头说明，再选择实现方式。静态材料适合阅读，实录适合展示操作，图解适合解释结构，角色适合承载态度，相机运动适合揭示空间关系。同一种动画贯穿所有内容，容易让长片失去层次。

### 1.1 把模糊评价翻译为可改的对象

| 反馈 | 应拆解的判断 | 可采取的动作 |
| --- | --- | --- |
| 不够灵动 | 是相机不动、主体不动、缺少视差，还是镜头没有信息变化？ | 建立贯穿数秒的运动，再安排前后景与遮挡 |
| 太空 | 是缺少主视觉、字号太小、信息位置失衡，还是叙事没有落点？ | 放大主对象、补充对应证据、用逐步图解建立重心 |
| 太乱 | 主视觉是否同时超过两个？背景与正文是否同亮？ | 减少同时激活的层，错开人物、主字和证据的高亮窗口 |
| 不像参考 | 偏离的是构图、材质、节奏、镜头深度还是文字运动？ | 对照同类镜头逐项修正 |
| 很廉价 | 是否主要依靠缩放、抖动、闪光，缺少空间与排版？ | 先修构图、字体、光值和运动动机 |
| 变化太突兀 | 是有意剪辑还是非预期状态跳跃？ | 查切点、姿态、坐标、局部时间、资源加载与渲染顺序 |
| 没有气势 | 是信息不聚焦、停留不够、音乐落点偏移，还是表演不足？ | 集中少数重音，给高潮之前和之后留出对比 |

评价必须落到可观察现象。修改后在同一观看条件下比较，记录改善了什么，以及是否引入新的阅读或连续性问题。

## 2. 第一步：把创作需求写成可验证的约定

### 2.1 需求中必须明确的事项

- 受众、主题、主要观点与希望观众完成的认知变化。
- 主要观看设备、画幅、预计长度、字幕语言与阅读条件。
- 风格参考各自负责什么。画面参考、音乐参考、叙事参考可以来自不同作品。
- 文稿是否已批准，配音是否稳定，哪些材料仍会替换。
- 必须出现的文字、视觉标志、声明、署名及其呈现顺序。
- 哪些时间是硬约束，哪些可以根据表演与音乐调整。
- 当前交付阶段是分镜、动态预演、可播放工程、成片还是公开发布。

将“音乐第十秒”和“全片第十秒”分开写。类似“标题保持到音乐结束”的指令，还要写明标题的入场、稳定阅读、退场与尾音之间的关系。一个模糊时标会影响画面、字幕和配乐整条链。

### 2.2 建立验收句

将目标写成可以直接观察的结果，例如：

> 两屏说明结束后才开始音乐。主标题出现时，人物已经让出中心区域。标题完整停留一个可读窗口，随后进入短转折，再接第一句旁白。

> 前言中的走道逐渐成为 PV 的入口。观众能够沿同一运动方向进入新场景，切点前后没有主体大小突变。

验收句应描述体验和证据。实现名称、函数名或效果名称放进制作说明，避免用“已经加了某特效”代替“观感达到什么程度”。

### 2.3 明确变更影响范围

文稿、配音、画面、字幕和音乐互相关联。改动前标记它属于以下哪种：

| 改动 | 可能受影响的下游 |
| --- | --- |
| 替换一句配音，文字相同 | 字词时标、停顿、口型、背景音乐让位、局部镜头长度 |
| 改写一个段落 | 所有上述项目，加上段后时间累积、论证顺序与证据 |
| 插入一个 PV | 后续全片时间、章节入口、配乐区间和导航 |
| 替换图片 | 宽高比、裁切、可读性、颜色、来源署名 |
| 修改镜头运动 | 文字位置、遮挡、转场端点、运动舒适度 |
| 增减片尾 | 音乐终点、全片时长、署名完整性、最后可见帧 |

只完成某一个文件的更新，不足以说明变更已进入最终成片。每阶段都要有明确选用版本。

## 3. 第二步：系统拆解参考作品

### 3.1 先验证参考材料提供了哪些信息

查看参考文件的画幅、时长、帧率、音轨、压缩和是否为屏幕录制。若只有画面轨，可以研究构图与运动；音乐落点需要另外的音源。若视频经历播放器录屏，还要识别鼠标、控制条、缩放与屏幕刷新带来的干扰。

先均匀抽帧看总体语法，再对重要转场做密集观察。均匀抽帧帮助理解结构，逐帧窗口帮助理解状态连续性。两者分别使用，避免从几张代表图推测整条动画。

### 3.2 用九个维度做参考镜头表

| 维度 | 需要记录的问题 |
| --- | --- |
| 构图 | 主体位置、留白、重心、边缘与画外空间 |
| 景别 | 全景、中景、近景如何交替，尺度如何变化 |
| 相机 | 位移、旋转、推进、后撤、跟随及停住的时刻 |
| 层级 | 背景、主体、信息与前景各占多少注意力 |
| 文字 | 字体气质、字重、行距、阅读窗口与进出方向 |
| 色值 | 大面积明暗、强调色的用途、人物与背景分离 |
| 材质 | 摄影、版画、颗粒、纸张、扫描线是否有统一逻辑 |
| 节奏 | 信息多久变化一次，何时密集、何时安静 |
| 转场 | 上一镜留下什么，下一镜从哪里接住 |

对每个参考片段写出“可迁移机制”。例如，深色门框从镜头前经过，形成一次遮挡，从而允许人物换姿。机制明确后，可以换成树干、立柱、文字块或前景设备，仍能保留连续性。

### 3.3 从模仿走向适配

先找到参考最稳定的三五条规则，形成风格约束。比如主字始终占据安静区域、前景移动快于背景、强调色只用于关键词、相机在信息阅读时减速。再把自己的文稿映射进去。

参考中的每个对象都有语义。复制其视觉关系时，也要给新对象相应动机。证据页需要阅读，不能机械沿用人物掠过镜头的速度；声明需要清楚，不能直接照搬高潮段的多层纹理。

## 4. 第三步：将文稿改写成视听结构

### 4.1 给每段确定画面任务

长片的段落通常可分为提出问题、展示事实、解释机制、比较反差、情绪推进、概括转折和收束。先给每段标注任务，再选择画面。

| 段落任务 | 优先画面 |
| --- | --- |
| 提出问题 | 大字、明确的视觉对象与有意停顿 |
| 展示事实 | 证据、文献、界面、现场或操作实录 |
| 解释机制 | 分步图解、关系连线、因果演示 |
| 比较差异 | 稳定对照布局、前后同条件演示 |
| 推进情绪 | 主体靠近、视线集中、强调字与音乐重音 |
| 概括转折 | 清场、构图重组、新的镜头方向 |
| 收束 | 已建立意象的回归、结句、署名或献词 |

保持多样性需要有结构。事实段落连用多个不同截图，也可能产生同一种阅读疲劳；应在合适位置加入图解、实录、短暂停顿和空间过渡。

### 4.2 建立语义锚

每个镜头记录它对应的短语、动作或声响。语义锚比固定秒数更能经受改稿。例如“旁白说到工具被接续时，第二个节点出现”，比“第八秒出现第二节点”更容易随新录音适配。

时间表仍然需要秒数，但它应由当前录音和锚点推导。换录音后先重建锚点，再检查画面节奏，避免让所有下游场景按一个倍率统一变速。

### 4.3 让图解随论证展开

节点、箭头和中心结论依次出现。先让观众认识对象，再解释关系，最后呈现总结。循环图可先显示起点，沿连线到达后逐个出现新节点，环闭合时再显示中心命题。

每一步至少包含到达、阅读和离开三个阶段。箭头的生长方向要符合因果方向，主句的出现时间要对应旁白。对于复杂图，不必每个框都平均分配时间；时间按新概念数量和理解难度分配。

## 5. 第四步：先分析声音，再安排视觉高潮

### 5.1 音乐分析的层次

先完整听取将要使用的段落，标记进入、发展、重音、回落、尾音与可剪接乐句。再用波形、短时能量、起音、频谱或节拍候选辅助定位。

自动 BPM 候选可能存在半速、倍速和拍位偏移；高能量也可能是持续音，而非适合切镜的瞬态。频谱变化可以说明密度与亮度变化，具体乐器和和声需要相应听审或乐谱依据。

应分别记录：

- 原曲源时间。
- 剪辑后编排音乐的时间。
- 视频使用这段音乐的入点。
- 镜头实际动作的时间。
- 听审确认、算法候选与人工决策的区别。

### 5.2 给重音分级

一个音乐段落可分为持续运动、局部强调和结构重音。持续运动由相机、轨道、颗粒和背景承担；局部强调用于关键词或一个动作；结构重音用于主标题、场景展开或章节交接。

将重要重音全部分配出去后，主动保留一些不切镜的拍点。视觉密度的变化能形成层次。标题落定后的稳定停留，经常比不断加速运动更有力量。

### 5.3 修改音乐时保护既有锚点

需要延长或缩短音乐时，先选可衔接的局部乐句。记录源区间、重复或拉伸范围、交叉窗与时间映射。改完核对鼓点、低频、混响尾和人声残留。

局部编辑之后，之前的高潮可以保持原位，之后的高潮应重新定位。避免凭源曲秒数直接控制已编排音乐。任何拉伸都要试听音色与节奏，参数范围只能作为尝试起点。

## 6. 片头设计：用有限时间建立观看预期

### 6.1 片头要完成的工作

片头通常需要建立主题、视觉世界、节奏与进入正文的方式。如果必须包含声明，将其阅读任务与后续情绪任务分别安排。开场歌曲何时启动，应该是清楚的制作决定。

片头的总时间可写成：

```text
片头总长
  = 信息说明窗
  + 音乐与主题展示窗
  + 主标题阅读与退场窗
  + 转折或正文接棒窗
```

窗口可以重叠，例如标题的稳定阅读与音乐淡出同时发生。每个重叠都要说明哪一层在主导注意力。

### 6.2 时间卡不等于镜头重启

片头可能需要快速呈现多个日期、成就或关键词。信息卡可以频繁变化，底层相机仍沿同一空间持续移动。将信息切换、角色变化和相机运动写成三条独立轨，便于控制节奏。

角色进入时先建立位置、大小和方向；交接时继承空间关系；标题出现前让主体退出阅读区。每次日期更新都同时重置背景、角色与镜头，容易形成翻页演示感。

### 6.3 日期、标题与次级信息分别排版

日期承担定位，关键词承担意义，图表或注释提供补充。给它们不同的字号、字重、亮度和位置。以实际播放大小检验，而非只看全屏编辑画布。

阅读时间应包含眼睛找到文字所需时间。若一张卡总共两秒，入场和退场各半秒，稳定阅读只剩一秒。长句、陌生术语和复杂日期应减少字数、提前出现或延长窗口。

主标题可分三阶段：

1. 环境和人物开始让出空间。
2. 主字进入并在可读位置落定。
3. 保持、收束，再交给下一段。

标题的最高图层优先级不能解决所有问题。图表曲线、图例或主字发生遮挡时，仍需改布局。层序正确与信息可读分别验收。

### 6.4 多角色如何形成旅程

为角色安排不同的叙事职责，如观察、创造、回应和展望。每个造型要在动作、视线与构图上承担任务。

交换素材可选三种方法：

| 方式 | 适用情况 | 关键条件 |
| --- | --- | --- |
| 遮挡交换 | 两张姿态变化较大 | 前景短时覆盖重要轮廓，交换后方向与尺度连续 |
| 姿态匹配 | 同一人物相似构图 | 头部中心、视线、肩线和视觉重心接近 |
| 有意切镜 | 强重音或叙事转折 | 新构图清楚，切换具有节奏与语义动机 |

透明叠化适用于可兼容的画面。若两张角色大小、头部位置差很多，叠化中间会出现双脸或双身体，持续时间再短也可能被察觉。

### 6.5 声明、黑场与转折

声明页可沿用片头材质，但需要降低背景复杂度，保护完整文字。标识和必须准确的内容使用可信原始素材，排版层独立。

黑场是一段有长度的镜头。规定黑场从哪一帧开始、声音是否继续、转折文字何时出现、正文何时接入。若要求纯黑，需检查最终像素；若需要保留尾音，也要明确可闻结束点。

片头验收至少包括说明→音乐、信息卡切点、人物交接、标题清场、音乐淡出、黑场和正文接棒。重复播放、暂停恢复与首次播放也要纳入。

### 6.6 一套可以直接起草的片头镜头表

下表提供功能顺序，长度根据实际音乐和文字决定。

| 镜头 | 主视觉与运动 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| 建立世界 | 一个清楚的空间或主题对象，相机开始沿主方向移动 | 必须阅读的信息已展示到位 | 观众能辨认主题环境 |
| 展示过程 | 日期或事件逐个出现，底层运动连续 | 当前事件有足够阅读空间 | 主信息读完，下一事件有语义衔接 |
| 主题聚焦 | 角色、意象或证据成为短时主体 | 音乐进入更强结构段 | 主体完成动作并开始让位 |
| 标题落定 | 前景清理，标题进入稳定区域 | 主要对象已退出冲突区 | 标题达到完整阅读时长 |
| 正文接棒 | 保留一个位置、对象、运动或声响作为桥梁 | 标题与音乐收束可同时成立 | 正文第一镜成为唯一当前场景 |

若使用多角色，在“展示过程”中先用简化色块预演运动，确认人物数量、重叠与读区，再换正式素材。这样可以在投入精细素材之前发现构图冲突。

## 7. PV 设计：把主题发展成一次完整的情绪运动

### 7.1 先定义 PV 的叙事角色

PV 可以用来提出问题、展示世界、浓缩论点、建立制作信誉或形成章节转折。根据目的决定它需要多少文字、多少证据与多少纯视觉运动。

一个可复用的结构是：主题提问、问题扩展、证据或意象展开、贡献与来源、主标题、面向下一章的终问。每段都需要节奏变化。连续一分钟的同类大字冲击，很容易损耗注意力。

### 7.2 问题群需要主次

问题之间应有逻辑递进。将其中一个设为主问题，其余围绕事实、机制、后果与选择展开。使用大词与完整句两个阅读尺度时，要明确两者分工。

同一句话同时出现在画面中央、艺术字和底部字幕，通常增加重复阅读。可以让画面呈现关键词，字幕呈现口播全文；没有口播时，则让完整问题成为唯一主读层。

### 7.3 证据段主动减速

书籍、档案、统计和界面需要观众辨认来源。文献卡保持统一标题区、页码区和引文区。一次只突出当前需要理解的内容，其余信息保持可访问或次级显示。

影像引用进入前，预留清场窗口；进入后保持稳定容器；离开时与下一层共用构图锚点。把证据做成高速掠过的纹理，会削弱它支持论证的作用。

### 7.4 空间语法贯穿全段

经纬网、轨道、建筑透视、光束、纸张或人物可以构成共同空间。它们应共享相机方向与消失点，远近速度合理，视觉强调有节制。

空间中固定的主文字应保持编排层级。漂移对象如果因为细微深度变化不断交换透明层顺序，会产生闪烁。将有意穿越的对象与稳定排版对象分别排序。

角色可以成为前景主体，也可以成为环境剪影。两种角色身份各有可见度和时间窗。口型只在需要表达说话时启用，音乐段的起音可用于其他动作或留作节奏分析。

### 7.5 PV 中的署名与制作信息

将来源和贡献者看作可读内容。名字、角色、曲目和材料类别使用一致版式。每幕只交代少量重点，完整目录另有稳定载体。

制作统计需明确统计对象与日期。账号、仓库、插件和个人分别计数，避免把技术目录的条目数写成独立自然人数。动画可以强调规模，文字解释应保持准确。

## 8. 一镜到底与无缝衔接

### 8.1 连续性的五个层面

| 层面 | 要保持的关系 |
| --- | --- |
| 空间 | 主体位置、消失点、景深及镜头方向 |
| 运动 | 速度、加速度、旋转趋势与动作相位 |
| 视觉 | 亮度、色相、材质与轮廓变化 |
| 语义 | 观众为何从当前对象走向下一对象 |
| 声音 | 旁白收声、环境连续、音乐起势与重音 |

位置连续只是基础。上一镜向右快速运动，下一镜突然静止，即使对象落在同一点也可能有顿挫。重要转场同时检查端点位置与速度；需要停住时，提前安排减速。

### 8.2 入口用真实下一场预滚

先确定一个可进入的对象，如门、屏幕、纸面、地图或文字孔洞。镜头朝它推进，下一场的真实渲染在对象内部提前出现。遮罩扩展为满画时，下一场已到自己的正式起点。

把下一场的预滚时间定义为负值是可行方法。预滚与正式段使用同一相机函数、素材和布局；切点处变换归一。这样正式进入后不会再从另一套初始尺寸重新开始。

遮罩端点需满足：

- 起点的可见权重符合上一镜构图。
- 终点的不透明区域完整覆盖画面，包含四角。
- 羽化区不把旧画面残留在边缘。
- 下一场尺度、中心和姿态在切点达到正式状态。
- 字幕、角色与声音的启用条件互相协调。

### 8.3 出口提前揭示真实下一章

最后几秒在下层绘制真实章首，上层 PV 通过遮罩退去。章首可以缓慢归位，正式入口时达到标准尺度。章首预滚需要明确定义是否播放旁白、是否出现字幕，防止画面预载顺带触发声音。

采用圆形揭幕时，终点覆盖半径要大于画面中心到最远角的距离，再计入羽化余量。矩形门洞同理，扣除羽化后的实心区域仍要覆盖画布。用几何条件验收，能避免角落残留。

### 8.4 让前后两镜共用端点

为转场写“上一镜结束状态”和“下一镜开始状态”，包括相机、主体、文字、遮罩及音量。对关键位置使用共同参数，减少分别调整产生的偏差。

绘制真实下一场比复制一张看起来相同的截图更容易维持口型、粒子和相机状态。必须使用截图时，应明确定义冻结姿态，避免进入真实场景后立即跳到另一时刻。

## 9. 片尾设计：从结论过渡到贡献者与余韵

### 9.1 将结句与署名之间的交接单独设计

结句需要清楚、自然地完成表达。署名需要新的阅读速度。预先决定音乐是否在结句之前进入、对白何时停止、片尾何时取得主视觉、最后一句字幕何时退场。

一种常用方法是音乐提前低电平进入正文，结句完成后由音乐独占，画面缓慢转入名单。另一种是有意留白后再起片尾曲。选择取决于语义与尾音，写清全部窗口。

### 9.2 片尾有自身的起承转合

可将片尾组织为主题回望、核心署名、完整贡献目录、形象变化、献词与收光。大量名单可以形成路径、轮廓或群体意象，但阅读区与重点姓名应始终明确。

数据与动画分离。名单表至少保存显示名、类别、贡献、来源、排序、统计日期与必要备注。组织账号与个人分别描述。重复显示、跨类别出现和合并规则应可追溯。

制作前用真实长度的姓名、组织名和贡献说明填充一版名单。短占位词排得下，并不能证明正式名单不会溢出。至少试最长名称、双语名称、空类别和极少条目的情况，检查自动换行、分组留白与排序。

### 9.3 大量对象的表现与性能

按可见窗口或邻近分组加载、布局与绘制。静态字形可缓存为纹理，复杂排版提前计算。相机持续运动，不必让每个名字都独立跑一套随机动画。

名单从文字转为图形时，保持可追踪的运动方向与对象关系。最终献词出现前主动减少信息密度，让观众从检索名字的状态回到作品主题。

### 9.4 末帧与尾音

规定最后一个可读句、最后一个可见动作、纯黑开始和音频结束。深色遮罩不一定产生纯黑；渐弱也不一定已不可闻。若交付需要黑尾或保留尾音，给出帧数与采样边界。

片尾跳转按钮、章节导航、音乐标尺和实际绘制共用时间转换。设计时长变化后，不能只缩放动画而让导航沿旧秒数跳转。

## 10. 素材与角色制作

### 10.1 每项素材有明确用途

按叙事角色把素材分为证据、环境、主体、图解元素和装饰。证据要求真实可读，环境要求空间稳定，主体要求身份一致，图解元素要求关系清楚。用途决定生成、查找、裁切和运动方式。

复用现有素材时，先检查完整原图与源片段。缩略图无法证明细节、透明边、真实比例、背景音和动作区间都合适。

### 10.2 角色图以系列方式设计

定义一张身份基准表，记录头身比、脸部轮廓、发色与配饰、衣饰结构、标志、肢体和尾部等特征。每张图同时指定视线、动作、景别、画外留边、光线和下一镜衔接方向。

“成熟”“活泼”“严肃”等描述应转化为姿态与比例约束。角色的可爱程度、头身比和场景情绪共同影响年龄感。与目标风格冲突时，重新挑选或生成符合身份的图。

透明图检查真实 alpha、边缘残留、裁切安全边、手与道具完整性、阴影归属。动画所需的外延空间应在生成前规划。只生成一张贴边角色后再强推近景，容易露出裁切与分辨率问题。

### 10.3 静态图也能形成有意义的运动

采用相机运动、局部视差、遮挡、光值变化和姿态接棒。近景物体相对移动更明显，远景慢；所有层围绕共同观看方向。给一张图叠多种无关摆动，可能让动作看起来漂浮。

需要真实肢体运动时，使用具有相应能力的素材或模型。把视差效果用于适合它的镜头，验收轮廓、透视与关节是否自然。

## 11. 代码动画的时间架构

### 11.1 统一主时间，显式转换局部时间

```text
帧号 → 全片时间
       ├─ 片头时间 → 片头歌曲源时间
       └─ 正片显示时间
            ├─ 当前配音单元 → 音频源偏移
            ├─ 插入段局部时间
            ├─ 当前视觉场景 → 场景局部时间
            ├─ 素材累计可见时间 → 原视频位置
            ├─ 配乐时间 → 当前曲目的源秒与增益
            └─ 片尾时间 → 设计音乐标尺
```

每个函数说明输入时间属于哪条轴。插入、删除、停顿和重录使用映射表表达。语音时钟可以驱动实时播放；离线导出按绝对帧号求时间。动画求值不应依赖“上一帧恰好被播放过”。

相邻场景建议用半开区间 `[start, end)`，减少边界双激活。比较浮点时使用帧号、整数时间单位或合适容差，并明确舍入规则。

### 11.2 确定性绘制

理想接口能回答：给定时间、素材和配置，应画出什么。随机颗粒采用固定种子，镜头与图元尽量由解析函数求值。需要模拟的效果保存可重建状态或预计算缓存。

暂停、拖动、倒拖、重复播放和离线渲染都调用同一核心求值逻辑。播放方式影响时钟推进，不能改变构图定义。

预先定义“一致”的验收尺度。相同素材、主对象位置、字幕与语义锚应一致；包含物理模拟、角色模型或不同图形后端时，像素可能有微小差别。为关键状态设允许误差，重要镜头使用可重建状态或受控缓存。只有经过相应测试，才能宣称逐像素复现。

### 11.3 分开资源准备、状态求值与画布提交

```text
准备阶段
  读取配置、字体、媒体信息、初始帧

每次请求
  记录请求序号
  求出当前各时间轴与活跃层
  定位并等待所需媒体
  检查请求是否仍为最新
  重置画布状态并按稳定顺序合成
  提交画面及审计字段
```

过期异步请求不能覆盖新帧。快速拖动时可以合并中间请求，但应让调用方知道哪次渲染已完成。资源未准备好时使用构图一致的回退，或等待足够条件后提交。

### 11.4 画布和图层状态

明确每层是否包含坐标变换、裁切、混合、滤镜与透明度。作用域结束时恢复。主合成前重置必要状态，防止上一层影响字幕或下一幕。

字体载入后再量字和生成字纹理。透明层排序要稳定，视频容器保持定义好的目标框。画面安全区、字幕带和证据阅读区作为可检查约束。

### 11.5 将可移植的规则写进镜头契约

镜头数据至少包含叙事任务、时间域、主对象、阅读区、源素材区间、入退场状态、声音锚和验收条件。归一化坐标便于换分辨率，文字实际大小仍需按目标观看条件检查。

```yaml
shot_id: evidence_reveal
intent: "让观众看清一条证据，再理解它对应的判断"
time_domain: sequence_seconds
timing:
  enter_anchor: "旁白首次提到这份材料"
  readable_until: "关键句解释完成"
layers:
  background: environment
  main: evidence_card
  secondary: source_label
  foreground: optional_occluder
layout:
  main_box_normalized: [0.12, 0.10, 0.76, 0.70]
  fit_policy: contain
  caption_safe_area: bottom
motion:
  enter: "沿主镜头方向进入正式目标框"
  read: "位置稳定，允许轻微整体运动"
  exit: "与下一镜共享中心或由遮挡完成交换"
constraints:
  - "关键证据不能被角色或装饰挡住"
  - "资源载入前后目标框不变"
acceptance:
  - "首次加载与直接跳转构图一致"
  - "正式观看大小下能读到关键句和来源"
```

这里的坐标是说明格式的样例。真正的镜头契约应由该镜头的文本、素材比例和安全区共同确定。

## 12. 运动设计的具体方法

### 12.1 定义关键状态

对每个对象写出入场、稳定、强调、退出四个状态。位置、缩放、旋转、透明度、模糊和层级分别明确。不需要每个对象都有全部状态。

一次运动优先有一个主方向。相机推进时，对象可保持世界坐标；人物走过时，相机可缓慢跟随。这样运动有清楚参照系。

### 12.2 缓动决定动作性格

线性插值适合匀速移动；平滑入出适合由静止开始又回到静止；快速起步慢慢落定适合强调信息。连续镜头在某个关键点穿越时，不应随意使用使速度归零的缓动。

对连接的两段，检查端点位置和切线方向。若要保留动量，让前段末速度与后段初速度匹配；若要突然停住，需要重音或物理原因支持。

### 12.3 跟随、错峰与视差

视觉层次可以通过轻微时间差建立。主体先进入、关键词随后、注释最后；退场时可反向清理。错峰应服务阅读顺序。

视差依赖深度：前景移动相对更快，远景更慢，主体与相机关系稳定。屏幕固定文字应保持阅读稳定；世界中的文字才参与透视投影。

### 12.4 少量持续运动胜过同时扰动

背景、相机和主对象各有运动，但同一时刻只保留少数强变化。全屏闪光、持续抖动和多层缩放会抢占读屏资源，也增加长时间观看负担。通过方向、遮挡和尺度变化创造动感，更容易保持作品气质。

## 13. 系统排查动画跳变

### 13.1 先区分四类跳

| 类型 | 典型表现 | 排查对象 |
| --- | --- | --- |
| 几何跳变 | 先大后小、位置突然改变、裁切变了 | 目标框、初始姿态、容器与原图尺寸 |
| 时间跳变 | 动作从中间重启、角色突然换姿 | 局部时间、配音映射、可见时间累计、场景边界 |
| 资源跳变 | 空白后突然出现、首帧与后面不同 | 字体、图片decode、视频seek、首帧就绪 |
| 提交跳变 | 来回拖动出现旧画或闪回 | 异步顺序、请求序号、共享画布、缓存失效 |

先复现再判断。一个镜头可能叠加两类问题。

### 13.2 目标框先固定

图片和视频的目标框在资源就绪前后保持一致。原素材尺寸用于计算框内等比适配，不能让容器从默认全屏临时切到正式大小。

区分内接与外接裁切策略，写入镜头数据。对同一素材的阅读停留、强调推近和恢复，使用共享构图状态。没有共享端点时，切回普通镜头会再次跳。

### 13.3 记录可观察字段

至少记录时间域、场景 ID、素材 ID、源时间、目标矩形、缩放、透明度、层级、资源状态和渲染序号。用这些字段判断“哪一项发生不连续”。

检查切点前后几帧，并补一段真实速度播放。对比顺播、直跳、倒跳到同一时刻。只看静帧可能漏掉速度变化，只看播放可能误把解码延迟看作构图问题。

### 13.4 修复后检查同类镜头

横片、竖片、静图、角色模型、阅读停留、循环图和长实录都至少有代表样本。检查初次加载、暂停恢复、素材结束、跨章节和跨导出分块边界。

修好基础逻辑后再添加美术过渡。叠化可以美化有意交接，无法保证时间映射、加载和异步提交正确。

## 14. 声音、字幕与视觉如何共同工作

### 14.1 配音按语义驱动画面

以批准的当前录音建立首词、转折和末词锚点。保留自然气口，图解关键节点跟随语义。旁白较慢时可以增加证据阅读或持续相机运动；不要让画面每句都等到完全静止才进入下一句。

### 14.2 配乐的四个独立参数

源起点、视频入点、淡变时长和实际重叠分别记录。两首曲都淡四秒，不代表它们实际重叠四秒；后一首提前一秒进入，也不意味着它在语义锚点已经达到全音量。

交叉窗内测试起点、中点、终点和直接跳入。自然结束、显式截断和循环是不同策略。音乐切点应听旋律、低频相位、混响尾与人声。

### 14.3 响度与表演分开处理

配音的态度靠语气、节奏与发声，音量只控制听觉位置。配乐让位可由对白包络驱动，设置合理攻击和释放，防止抽吸。每条增益、总音量、限幅和最终重采样分别记录。

在典型耳机与外放条件下检查清晰度。峰值没有超幅，并不能证明人声易懂；响度够大，也不能证明表演有力量。

### 14.4 字幕、艺术字和图中文字

字幕服务听觉理解，艺术字强调主题，图中文字解释证据。三者可以共存，但位置与内容应分工。长句分行、标点、英文词、数字和专名分别检查。

字幕时标跟当前音频，图面文字可按语义节奏显隐。用末帧停留或静音插入改变段落后，重新核对字幕结束点，避免最后一行挂进署名。

## 15. 制作组织与迭代

### 15.1 先样板，再扩展

先做能代表作品难度的一镜，包含关键字体、人物、证据、声音与转场。用真实速度和目标观看大小判断，再扩展为片头或 PV。

静态关键帧确认美术方向，动态预演确认节奏，真实素材预览确认技术，导出小样确认交付。每个阶段解决它最能暴露的问题。

### 15.2 反馈形成变更卡

```yaml
issue_id: motion_014
semantic_anchor: "旁白提到第二阶段"
time_domain: sequence_seconds
symptom: "图片先全屏一帧，再回到左侧阅读框"
reproduction: [continuous_play, direct_seek]
observations:
  - "首帧容器使用了默认尺寸"
change: "容器从入场起使用正式目标框"
regression_checks:
  - "冷加载"
  - "倒拖"
  - "同类竖图"
status: pending_review
```

记录现象和证据，保留哪个方案被批准。用户连续改稿时，及时登记，按明确的影响范围更新队列，避免用旧稿覆盖新稿。

### 15.3 并行工作围绕明确接口

素材、配音、分镜、图解和工程可以并行，但每项需要稳定 ID 与交付格式。声音队列或渲染器这类共享资源应有唯一负责人。换参考、替换模型和重置时间轴必须显式通知依赖方。

### 15.4 版本选用是生产数据

将草稿、生成候选、通过版本、已导入版本与冻结导出分别标记。文件名只是提示，选用清单和哈希才描述真实依赖。修改关键输入后，缓存键也必须改变。

## 16. 导出与交付

### 16.1 冻结一组一致输入

冻结文稿、配音、字幕、音乐编排、素材、字体、动画配置与渲染器版本。在冻结副本里复核关键改动。预览用了新声音而导出读取旧目录，是常见版本错误。

按实际帧率用帧号求时间。明确场景首末帧、总帧数舍入、音频采样边界和尾帧策略。固定帧率文件仍需检查运动是否每帧都有正确状态。

### 16.2 性能优化先测瓶颈

视频解码、画布渲染、角色模型、纹理上传、图像读取和编码分别可能限速。先用代表段测吞吐、内存、显存和资源峰值，再设置并发。硬件编码加快的是编码部分。

缓存静态排版与纹理，释放闲置视频解码器；复杂段可单独控制 worker。提高并发后若掉帧、崩溃或重试增多，整体完成速度可能下降。

### 16.3 分块恢复必须识别输入版本

分块完成标记至少包含起帧、帧数、分辨率、帧率、渲染器版本和输入清单哈希。只有参数与内容一致才能复用。先写临时块，验证后确认完成。

合并前核对块顺序、总帧数、首末状态与音频。正式文件应经过规格探测、代表位置实播和完整解码检查。声音还需独立核对时长、峰值与关键转场。

### 16.4 原生分辨率与交付分辨率

提高输出尺寸可以满足文件规格，但细节取决于源画布、字体纹理和素材像素。若要求原生高分辨率，开工时就规划实际渲染尺寸并测代表帧。

### 16.5 可运行工程的交付

将代码、时间数据、素材、字体、依赖、来源与启动说明一起规划。路径可移植，服务器支持视频所需的字节范围请求，缺失资源有清楚错误。

在新的目录或独立环境验证，不依赖制作者未交付的服务。公开播放还要检查真实页面点击、长距离拖动、移动端、附件下载和校验。首页返回成功只能说明页面可访问。

## 18. 最后一次审片清单

- 开场是否明确主题，说明内容可读，音乐进入有意图？
- 每幕是否只有清楚的主视觉，背景、人物、证据与字幕是否互相让位？
- 日期和陌生术语是否有足够稳定阅读时间？
- 角色多形象是否具有动作或叙事关系，交换是否自然？
- PV 是否有问题推进、证据阅读、主题落定和通向下一章的出口？
- 转场首末位置、速度、尺度、遮罩覆盖和声音是否一致？
- 图解是否按理解顺序展开，连接线是否对应正确关系？
- 证据与统计的来源、日期、口径和署名是否明确？
- 同一时刻顺播、直跳、倒跳与离线绘制是否一致？
- 配音版本、字幕、配乐、图面文字和镜头长度是否来自同一选用清单？
- 结句是否完整，片尾名单是否可读，尾音和末帧是否按约定结束？
- 最终文件和工程包是否在目标播放条件与独立环境中验过？
